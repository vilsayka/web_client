# Тест-кейсы

## TC-API-001: Успешный вход

Предусловия: пользователь существует, пароль корректный.

Шаги:

1. Отправить `POST /api/v1/login` с `username` и `password`.
2. Проверить HTTP-статус.
3. Проверить тело ответа.

Ожидаемый результат: статус 200, в ответе есть `access_token`, `token_type=bearer`.

## TC-API-002: Неверный вход

Предусловия: пользователь существует, пароль неверный.

Шаги:

1. Отправить `POST /api/v1/login` с неверным паролем.
2. Проверить HTTP-статус.

Ожидаемый результат: статус 401, пользователь не авторизован.

## TC-API-003: Обновление токена

Предусловия: есть валидный Bearer-токен.

Шаги:

1. Отправить `POST /api/v1/refresh` с заголовком `Authorization`.
2. Проверить тело ответа.

Ожидаемый результат: статус 200, возвращен новый `access_token`.

## TC-COMP-001: Получение комплектующих по категории

Шаги:

1. Отправить `GET /api/v1/components/?category=Процессор`.
2. Проверить список элементов.

Ожидаемый результат: возвращаются процессоры, описание содержит характеристики компонента.

## TC-COMP-002: Неизвестная категория

Шаги:

1. Отправить `GET /api/v1/components/?category=Монитор`.

Ожидаемый результат: статус 400, ошибка `Unknown category`.

## TC-BUILD-001: Совместимая сборка

Шаги:

1. Отправить `POST /api/v1/build/check` со списком совместимых компонентов.
2. Проверить флаг совместимости.

Ожидаемый результат: `compatible=true`, список `conflicts` пустой.

## TC-BUILD-002: Конфликт сокета

Шаги:

1. Отправить `POST /api/v1/build/check` с процессором AM5 и материнской платой LGA1700.

Ожидаемый результат: `compatible=false`, в `conflicts` есть сообщение о несовпадении сокета.

## TC-ORDER-001: Создание заказа

Предусловия: пользователь авторизован как customer, компоненты существуют.

Шаги:

1. Отправить `POST /api/v1/orders/` со списком `component_ids` и `warranty_period`.

Ожидаемый результат: статус 201, заказ создан со статусом `ожидает сборщика`.

## TC-ORDER-002: Доступные заказы для сборщика

Предусловия: пользователь авторизован как importer.

Шаги:

1. Отправить `GET /api/v1/orders/available`.

Ожидаемый результат: статус 200, возвращен список доступных заказов.

## TC-ORDER-003: Запрет доступных заказов для customer

Предусловия: пользователь авторизован как customer.

Шаги:

1. Отправить `GET /api/v1/orders/available`.

Ожидаемый результат: статус 403.

## TC-GUAR-001: Создание гарантийного обращения

Предусловия: customer имеет заказ в статусе `собрана`, компонент входит в заказ.

Шаги:

1. Отправить `POST /api/v1/guarantees/` с `order_id`, `defective_component_id`, `problem_description`.

Ожидаемый результат: статус 201, обращение создано.

## TC-FE-001: Наличие основных страниц

Шаги:

1. Проверить наличие страниц `login.html`, `registration.html`, `create-pc.html`, `orders.html`, `my_guarantees.html`.

Ожидаемый результат: все файлы есть в `frontend/templates`.
