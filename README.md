# VibeCore

VibeCore — это удобное веб-приложение для сборки персонального компьютера с автоматической проверкой совместимости комплектующих, мониторингом актуальных цен и расчетом итоговой стоимости.

## 2. Описание

VibeCore позволяет пользователю подбирать компоненты для ПК (процессор, материнскую плату, видеокарту, оперативную память, накопители) из базы данных с реальными характеристиками. Система автоматически проверяет совместимость выбранных компонентов по ключевым параметрам: сокет, тип памяти, слоты расширения, энергопотребление. Приложение отображает актуальные цены и рассчитывает итоговую стоимость сборки.

## 3. Цели

1. Разработать Full Stack веб-приложение с микросервисной архитектурой.
2. Реализовать систему регистрации и аутентификации пользователей с использованием JWT.
3. Спроектировать и реализовать базу данных, содержащую минимум три связанные сущности, нормализованную по трём формам. Хранить пользователя с полями user_name, password_hash.
4. Реализовать поиск, фильтрацию, сортировку и пагинацию на уровне SQL-запросов.
5. Реализовать модуль для CRUD-операций.
6. Настроить репликацию базы данных Master-Slave.
7. Реализовать обязательные эндпоинты:
   - `/dashboard`
   - `/<username>`
   - `/about` и `/api/about`
   - `/api/hash/{str}`
8. Обеспечить защиту роутов от неавторизованного доступа.
9. Провести тестирование, задокументировать тест-кейсы, открыть Issues на GitHub с метками для выявленных дефектов, составить отчеты о тестировании.

## 4. Стек технологий

### Backend
- Язык: Python 3.13
- Фреймворки: FastAPI (Core/Business), Flask (Supporting/Admin)
- База данных: PostgreSQL с репликацией Master-Slave
- Работа с БД: psycopg2 (чистый SQL, без ORM)
- Аутентификация: JWT (python-jose) + bcrypt
- Статика и шаблоны: общая папка frontend/
- Документация API: Swagger UI (/docs)

### Frontend
- Технологии: HTML, CSS, JS
- Зависимости: itsdangerous==2.2.0, Jinja2==3.1.6, MarkupSafe==3.0.3
- Дизайн: Стилизация под Windows XP. Используется фреймворк XP.css (https://botoxparty.github.io/XP.css/)
- Адаптивность: компьютеры + медиазапросы (max-width: 768px, max-width: 480px). Режим администратора — строго для компьютеров.

### Data Engineering
- СУБД: PostgreSQL 18
- Инструменты: Python (psycopg2, json), Docker
- Репликация: Streaming replication

- Мастер: порт 5438
- Слейв: порт 5439

### Настройка репликации
1. Создан Docker-контейнер мастера с пробросом порта 5438
2. Настроены параметры репликации: wal_level = replica, max_wal_senders = 10
3. Создан пользователь replicator с правами на репликацию
4. Выполнен pg_basebackup для клонирования данных на реплику
5. Запущен контейнер реплики на порту 5439
6. Работа репликации проверена через pg_stat_replication

## 10. Описание БД (базы данных)

СУБД: PostgreSQL 18

Нормализация: 3 нормальная форма

Репликация: Streaming replication (Master-Slave)

### ER-диаграмма (текстовое описание)

Схема состоит из 6 таблиц:

- users — ядро системы с ролями (customer, importer, admin)
- importers — расширение для импортеров (связь 1:1 с users)
- orders — факты заказов (внешние ключи на customer и importer)
- components — каталог комплектующих с JSONB полем для гибких спецификаций
- pc_composition — bridge-таблица для связи many-to-many (orders ↔ components)
- service_guarantees — гарантийные обращения по дефектным компонентам

### Список таблиц

| Таблица | Назначение | Ключевые поля |
|---|---|---|
| users | Аутентификация и роли | user_id (PK), user_name, password_hash, role |
| importers | Данные сборщиков | importer_id (PK), user_id (FK), phone, email, full_name |
| orders | Заказы на сборку | order_id (PK), customer_id, importer_id, status, created_at, updated_at |
| components | Каталог комплектующих | component_id (PK), category, model, price, specifications (JSONB) |
| pc_composition | Состав сборки | composition_id (PK), order_id (FK), component_id (FK) |
| service_guarantees | Гарантийные обращения | guarantee_id (PK), order_id (FK), component_id (FK), description, status |

### Индексы и триггеры
- B-Tree индекс на users.user_name
- GIN индекс на JSONB поле components.specifications (быстрый поиск по характеристикам)
- Триггер update_modified_column() для автоматического обновления updated_at в orders

### Пример SQL-запроса с фильтрацией, сортировкой и пагинацией (без ORM)

```sql
-- Получение компонентов категории "Процессор" с ценой от 10000 до 50000,
-- сортировка по цене (убывание), пагинация (10 записей, страница 2)
SELECT component_id, model, price, specifications
FROM components
WHERE category = 'Процессор'
  AND price BETWEEN 10000 AND 50000
ORDER BY price DESC
LIMIT 10 OFFSET 10;
```

## 11. Архитектура проекта

Общая архитектура: микросервисная с выделением двух сервисов, взаимодействующих с общей базой данных.

### Core/Business сервис (FastAPI, порт 8000)

Вся клиентская бизнес-логика:
- Аутентификация и авторизация (JWT, bcrypt, ролевая модель)
- Конфигуратор ПК (компоненты, проверка совместимости)
- Жизненный цикл заказа (customer → importer)
- Гарантийные обращения
- Личный кабинет
- Дашборд с аналитикой (admin)

### Supporting сервис (Flask, порт 5000)

Административная панель для управления сущностями:
- CRUD для всех таблиц (пользователи, импортёры, заказы, компоненты, обращения)
- Поиск, сортировка, фильтрация
- Хэширование паролей через общую функцию из core/security.py

### База данных (PostgreSQL)
- Master — все операции записи (INSERT, UPDATE, DELETE)
- Slave — все операции чтения (SELECT)
- Разделение на уровне подключений: get_db_master() / get_db_slave()

### Особенности реализации
- Полное разделение на чтение (Slave) и запись (Master)
- Прямые SQL-запросы в репозиториях, отсутствие ORM
- JWT-токен содержит user_id, user_role, sub (username) для быстрой проверки прав
- Фронтенд взаимодействует с API через fetch, авторизация через заголовок Authorization: Bearer <token>

### 12.1 QA-документация

В рамках контроля качества проекта разработана следующая документация:

#### Тест-план (test_plan.md)

**Цель:** проверить качество проекта VibeCore до передачи пользователю: API, бизнес-логику, валидацию данных, базовые frontend-сценарии и регрессионную стабильность.

**Объект тестирования:**
- Backend API /api/v1
- Сервисы пользователей, комплектующих, заказов, гарантий и совместимости
- Pydantic-схемы входных данных
- JWT-аутентификация и проверка ролей
- Наличие ключевых HTML-страниц и JS-функций frontend

**Подход:**
- Ручная проверка покрыта чек-листом
- Автотесты написаны на unittest, не зависят от дополнительного тестового фреймворка
- API-тесты используют fastapi.testclient.TestClient
- Подключение к реальной БД заменено dependency overrides и mock-объектами
- Найденные дефекты оформлены в Issues

**Критерии входа:**
- Установлены зависимости из requirements.txt
- Переменная SECRET_KEY задана в окружении
- Запуск выполняется из корня проекта

**Критерии выхода:**
- Все автотесты проходят
- Для найденных дефектов есть описание, ожидаемое поведение и label
- Регрессионный чек-лист готов для ручного прогона перед релизом

**Риски:**
- Интеграционные тесты PostgreSQL БД не выполнялись

#### Чек-лист (checklist.md)

**Аутентификация:**
- [x] Пользователь регистрируется с валидными логином и паролем
- [x] Регистрация с уже занятым логином возвращает ошибку
- [x] Логин с валидными учетными данными возвращает Bearer-токен
- [x] Логин с неверным паролем возвращает 401
- [x] Refresh возвращает новый токен для валидного токена
- [x] Защищенные ручки не доступны без Bearer-токена

**Комплектующие и сборка:**
- [x] Список всех комплектующих возвращается сгруппированным по категориям
- [x] Фильтр по русской категории возвращает только нужный тип комплектующих
- [x] Неизвестная категория возвращает 400
- [x] Проверка совместимости возвращает compatible=true для корректной сборки
- [x] Проверка совместимости находит конфликт сокета CPU/материнской платы
- [x] Проверка совместимости находит конфликт RAM/материнской платы
- [x] Проверка совместимости находит недостаточную мощность блока питания
- [x] Проверка совместимости находит неподдерживаемый форм-фактор корпуса

**Заказы:**
- [x] Customer создает заказ из существующих комплектующих
- [x] Создание заказа с несуществующим компонентом возвращает 404
- [x] Customer видит свои заказы
- [x] Importer видит доступные заказы
- [x] Customer не видит список доступных заказов сборщика
- [x] Importer принимает свободный заказ
- [x] Importer не может принять уже занятый заказ
- [x] Статус меняется только по цепочке: ожидает сборщика → на сборке → собрана
- [x] Importer не может менять чужой заказ
